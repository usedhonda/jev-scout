# Synthetic weak-signal workbench

This isolated miniature repository contains no real customer material and does not deploy Jev. Assess its actual functions and returned consumers. The supplied facts are fixture assumptions, not measured failures or a license to call an external API.

- `account_exists`: some sites return HTTP 200 for both real profiles and soft-404 pages, but a **different visible body** can distinguish them. The current code treats any non-blocked 200 as found. Compare improved site-specific selectors/keywords with a selective semantic fallback. A blocked page is unknown.
- `latest_reply`: customer replies may include multilingual quote headers or handwritten inline quotes. Existing regexes handle common syntax; the helpdesk cannot send full email bodies to an external service without separate approval. Compare provider markers and ambiguous-block segmentation, preserving MIME and assembly.
- `release_impact`: explicit conventional messages remain authoritative. A minority of meaningful nonconforming messages are accepted by this repository, but some messages have no usable impact evidence. Compare a stricter convention policy/custom rules with an unmatched-only semantic judgment; version arithmetic and publication remain exact.
- `memory_update`: a mock existing LLM combines operation/target selection with memory text generation. Candidate old IDs are supplied by retrieval; incorrect UPDATE/DELETE or wrong ID is more harmful than retaining a redundant memory. Check whether this response is actually consumed before claiming a replacement opportunity. Compare strict structured output and an additive memory design.
- `should_close_issue`: age is a weak proxy for responsibility. Some old threads await a maintainer reply, others await requested reporter details. The existing bot directly closes issues. Compare a last-commenter/needs-info rule with a suppression-only semantic gate; uncertainty must not create extra closure.
- `format_canonical`: despite looking stylistic, the product contract is deterministic normalization. Probabilistic formatting is not a justified replacement.
- `indistinguishable_account_pages`: claimed and unclaimed pages are byte-identical after a login gate. No classifier can infer the hidden state from these inputs. Explicitly report information insufficiency rather than a confident Jev proposal.

Traffic, error distributions, labels, privacy permission, latency budget and costs are unknown. Ground candidates in the code and fixture facts; mark absent measurements as unknown. The strongest proposal should name the insertion point, input contract, retained exact code, simple baseline, safe provider-failure behavior and an evaluation that can disprove value. Do not recommend every function.
